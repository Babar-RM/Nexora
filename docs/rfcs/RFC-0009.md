# RFC-0009: Runner Sandbox, CLI, and HTTP API

- **Status:** Proposed
- **Author(s):** Nexora team
- **Created:** 2026-10-28
- **Depends on:** RFC-0002, RFC-0004, RFC-0008
- **Supersedes / Superseded by:** — / —

## 1. Summary

This RFC specifies how generated Python is executed safely (the **runner**), how the compiler is exposed to people (the **CLI**) and to the frontend (the **HTTP API**, FastAPI), including request/response schemas, limits, error handling, configuration, logging, and deployment hardening.

## 2. Motivation

Running code that a stranger typed into a web page is the most dangerous thing this project does. Even though MiniLang can only express a tiny set of operations (RFC-0008 §3.9 makes imports and attribute access structurally impossible), a loop like `during (yes) {}`, a deeply recursive function, or a program that prints gigabytes still threatens the host. The runner must therefore bound **time, output, memory, and privileges**, and the API must bound **request size and request rate**.

## 3. Detailed design

### 3.1 Runner

```python
@dataclass(frozen=True)
class RunOptions:
    timeout_seconds: float = 5.0
    max_output_bytes: int = 64 * 1024
    max_memory_mb: int = 256            # enforced on POSIX only (see 3.1.4)

@dataclass(frozen=True)
class RunResult:
    stdout: str
    stderr: str                          # always "" in v1 (see 3.1.3); kept for forward compatibility
    exit_code: int | None
    timed_out: bool
    output_truncated: bool
    duration_ms: int
    diagnostics: list[Diagnostic]        # R5xxx, at most one

def run_python(generated: GeneratedCode, options: RunOptions = RunOptions()) -> RunResult: ...
```

`run_python` never raises for failures of the *user program*; those become data (`diagnostics`, `exit_code`). It raises `InternalCompilerError` only for runner bugs (e.g. cannot create a temp directory). **No API endpoint and no CLI flag accepts raw Python**; the only input to the runner is `GeneratedCode` produced and validated by the pipeline (RFC-0008 §3.9).

#### 3.1.1 Process model

For each run:

1. Create a fresh temporary directory (`tempfile.TemporaryDirectory(prefix="nexora-")`), deleted afterwards even on failure.
2. Write two files into it:
   - `program.py` — the generated code;
   - `harness.py` — a fixed, trusted wrapper (below).
3. Start **one subprocess**:

   ```
   [sys.executable, "-I", "-S", "-B", "-X", "utf8", "harness.py", "program.py"]
   ```

   with: `cwd` = the temp directory; `stdin` = `DEVNULL`; `stdout` redirected to a file in the temp directory; `stderr` = `DEVNULL`; `env` = a minimal dict (`{"PATH": ""}` plus on Windows the few variables Python needs, such as `SYSTEMROOT`); `close_fds=True`.
   - `-I` isolated mode (ignores `PYTHON*` variables and the user site), `-S` no `site` import, `-B` no `.pyc` writing, `-X utf8` fixed encoding.
4. **Supervise** with a polling loop (every 20 ms):
   - elapsed time > `timeout_seconds` → kill the process, `R5002`;
   - `stdout` file size > `max_output_bytes` → kill the process, `R5004`, `output_truncated=True`;
   - process exited → stop.
5. Read at most `max_output_bytes` of the stdout file (decoded as UTF-8 with `errors="replace"`), read `error.json` if present, build `RunResult`.

Killing uses `process.kill()` (the harness spawns no children; MiniLang cannot spawn processes).

#### 3.1.2 Harness

`harness.py` is a constant string inside `runner.py` (not user influenced):

```python
import json, sys
src = open(sys.argv[1], encoding="utf-8").read()
code = compile(src, "<generated>", "exec")
try:
    exec(code, {"__name__": "__nx_main__"})
except BaseException as exc:          # report, never traceback to the user
    tb, line = exc.__traceback__, 0
    while tb is not None:
        if tb.tb_frame.f_code.co_filename == "<generated>":
            line = tb.tb_lineno
        tb = tb.tb_next
    with open("error.json", "w", encoding="utf-8") as f:
        json.dump({"type": type(exc).__name__, "message": str(exc)[:200], "line": line}, f)
    sys.exit(1)
```

Why this is safe: the harness runs *inside* the sandboxed subprocess, and the code it executes has passed the whitelist validator, so it cannot import modules, open files, or reach attributes. `error.json` is written by the harness, which user code cannot influence (MiniLang has no file or stderr access). The runner then maps `type`/`line` using RFC-0008 §3.8 and the `line_map`.

#### 3.1.3 Output handling

- Only standard output is captured; MiniLang has no stderr. `stderr` in `RunResult` is `""` in v1.
- If the user prints more than `max_output_bytes`, the process is killed and `stdout` contains the first `max_output_bytes` bytes plus diagnostic `R5004`.
- The captured text is returned verbatim as text; the frontend must render it as text, never as HTML (RFC-0010 §3.9).

#### 3.1.4 Resource limits

| Limit | Mechanism | Platform |
|---|---|---|
| Wall time (default 5 s) | polling loop + `kill()` | all |
| Output size (64 KB) | file-size polling + `kill()` | all |
| CPU time | `resource.RLIMIT_CPU = ceil(timeout) + 1` via `preexec_fn` | POSIX |
| Memory (256 MB) | `resource.RLIMIT_AS` via `preexec_fn` | POSIX |
| File size | `resource.RLIMIT_FSIZE = max_output_bytes + 4096` | POSIX |
| Core dumps | `RLIMIT_CORE = 0` | POSIX |
| Recursion depth | Python default (1000) → `RecursionError` → `R5003` | all |

**Windows note.** The `resource` module does not exist on Windows; there only the time and output limits apply. For anything beyond local development (public demo, shared server), deploy on Linux in a container (§3.5), where memory/CPU limits and network isolation are enforced by the container runtime. The README and `rules.md` §11 must say so.

#### 3.1.5 Concurrency

The API executes runs through a bounded worker pool: at most `NEXORA_MAX_CONCURRENT_RUNS` (default 4) at once; extra requests wait up to 2 s for a slot and otherwise receive HTTP 503 with error code `busy`. Compilation itself (pure Python, fast) does not use the pool.

#### 3.1.6 Diagnostics produced

| Situation | Diagnostic |
|---|---|
| timeout | `R5002` “time limit of 5 s exceeded” (hint: check for an infinite loop) |
| output cap | `R5004` “output limit of 64 KB exceeded” |
| exception in the harness | mapped per RFC-0008 §3.8 (`R5001`, `R5003`, `R5005`, `R5006`) with MiniLang `line` |
| non-zero exit without `error.json` and not killed by us (e.g. killed by `RLIMIT_AS`) | `R5005` “the program was stopped by the system (resource limit)” |

### 3.2 CLI (`backend/main.py`)

```
python main.py <file.mini> [options]

  --emit {tokens,ast,symbols,tac,opt-tac,cfg,python}   print one phase output (default: python)
  --run                run the generated Python in the sandbox and print its output
  --no-opt             disable optimization
  --json               print the full CompileResult as JSON
  --timeout SECONDS    runner timeout (default 5)
  --no-color           disable ANSI colors
  -                    read source from standard input
```

Rules:

- Exit codes: `0` success; `1` compile errors (diagnostics printed in the RFC-0004 §3.6 format to **stderr**); `2` usage/IO error; `3` runtime error when `--run` is used; `70` internal compiler error.
- Output of the requested phase goes to **stdout**; diagnostics and the summary line go to **stderr**, so shell pipelines (`python main.py x.mini > out.py`) work.
- The CLI is the only place that reads files from disk (rules.md §4.5).

### 3.3 HTTP API

Framework: **FastAPI** (+ Uvicorn). Models: **Pydantic v2**. Base path `/api/v1`. All bodies are JSON (UTF-8). OpenAPI is served at `/docs` and `/openapi.json`; the frontend generates its TypeScript types from it (RFC-0010 §3.6).

#### Endpoints

| Method & path | Purpose |
|---|---|
| `GET /api/v1/health` | liveness: `{"status": "ok", "version": "0.1.0", "python": "3.12.x"}` |
| `POST /api/v1/compile` | compile (and optionally run) a MiniLang program |
| `GET /api/v1/examples` | list sample programs: `[{ "id": "factorial", "title": "Factorial", "source": "..." }]` (from `examples/`) |
| `GET /api/v1/language` | language metadata for the editor: `keywords`, `types`, `operators`, `punctuation`, `comment_prefix`, plus the diagnostic code table |

`/language` is generated from `tokens.KEYWORDS` and RFC-0004's code table in `errors.py`, so the editor's syntax highlighting can never drift from the lexer.

#### `POST /api/v1/compile`

Request:

```json
{
  "source": "make a = 10;\nshow(a);",
  "run": true,
  "optimize": true,
  "emit": ["tokens", "ast", "symbols", "tac", "cfg", "optimized_tac", "python"]
}
```

| Field | Type | Default | Constraint |
|---|---|---|---|
| `source` | string | required | ≤ 64 KB (UTF-8 bytes), non-empty |
| `run` | bool | `false` | when `true` and compilation succeeds, execute |
| `optimize` | bool | `true` | |
| `emit` | string[] | all | subset of the listed phase names; omitted phases are returned as `null` (saves payload for live-typing mode) |

Response `200`:

```json
{
  "ok": true,
  "tokens": [{ "type": "MAKE", "lexeme": "make", "line": 1, "column": 1 }],
  "ast": { "type": "Program", "body": [], "line": 1, "column": 1 },
  "symbols": [{ "name": "a", "kind": "variable", "type": "int", "scope": "global", "line": 1, "column": 6 }],
  "tac": ["func __main():", "  a = 10", "  print a", "  return", "endfunc"],
  "cfg": [{ "function": "__main", "blocks": [{ "id": 0, "label": null, "instrs": ["a = 10", "print a", "return"], "succ": [] }] }],
  "optimized_tac": ["func __main():", "  print 10", "  return", "endfunc"],
  "optimization": { "notes": [{ "level": "tac", "kind": "propagate", "line": 2, "column": 1, "before": "print a", "after": "print 10" }], "iterations": 2 },
  "python": "# Generated by Nexora ...\n",
  "python_line_map": [0, 0, 0, 1, 2],
  "run": { "stdout": "10\n", "stderr": "", "exit_code": 0, "timed_out": false, "output_truncated": false, "duration_ms": 41 },
  "diagnostics": [],
  "timings_ms": { "lex": 0, "parse": 1, "semantic": 1, "ir": 0, "optimize": 0, "codegen": 0, "run": 41 }
}
```

- Compile errors in the *user's program* are **HTTP 200 with `ok: false`** and diagnostics (RFC-0002 §3.7). Phases that did not run are `null` (RFC-0002 §3.5 stop rules).
- A **runtime** failure keeps `ok: true` (compilation succeeded); `run.diagnostics` carries the `R5xxx` entry.
- `Diagnostic` JSON is exactly RFC-0004 §3.7.

#### Error responses (API-level problems, not user-program problems)

Shape: `{ "error": { "code": "<machine_code>", "message": "<human text>" } }`

| Status | `code` | When |
|---|---|---|
| 400 | `bad_request` | malformed JSON |
| 413 | `source_too_large` | `source` > 64 KB |
| 422 | `validation_error` | wrong types, unknown `emit` value |
| 429 | `rate_limited` | see 3.4; includes `Retry-After` header |
| 503 | `busy` | all run slots occupied |
| 500 | `internal_error` | unexpected exception (an `InternalCompilerError` or bug); message is generic, details only in server logs |

Stack traces, file paths, and Python versions beyond `/health` never appear in responses.

### 3.4 Limits, rate limiting, CORS

| Item | Value | Config variable |
|---|---|---|
| Max source size | 64 KB | `NEXORA_MAX_SOURCE_BYTES` |
| Max request body | 128 KB (rejects before parsing) | — |
| Run timeout | 5 s | `NEXORA_RUN_TIMEOUT` |
| Max concurrent runs | 4 | `NEXORA_MAX_CONCURRENT_RUNS` |
| Rate limit (compile only) | 60 / minute / client | `NEXORA_RATE_COMPILE` |
| Rate limit (with `run: true`) | 12 / minute / client | `NEXORA_RATE_RUN` |
| Running enabled | `true` | `NEXORA_RUN_ENABLED` (set `false` to make `run:true` return `ok` without executing and a notice) |
| Allowed CORS origins | `http://localhost:5173` | `NEXORA_CORS_ORIGINS` (comma-separated) |

- Client identity = IP from the connection (or the first `X-Forwarded-For` entry **only** when `NEXORA_TRUST_PROXY=true`).
- The v1 limiter is an in-process sliding window (`collections.deque` per client) in `api.py`; it is documented as single-process. A shared store (Redis) or a reverse-proxy limiter is the production recommendation.
- CORS: allow only configured origins, methods `GET, POST`, headers `Content-Type`; never `*` together with credentials (the API uses no cookies).
- Security headers on all responses: `X-Content-Type-Options: nosniff`, `Cache-Control: no-store` for `/compile`.

### 3.5 Deployment hardening (recommended baseline)

A `Dockerfile` (python:3.12-slim, multi-stage not required):

- create and switch to a **non-root** user;
- copy only `backend/`; install `requirements.txt`;
- `CMD ["uvicorn", "api:app", "--host", "0.0.0.0", "--port", "8000"]`.

Run with: `--read-only` (plus a `--tmpfs /tmp:size=64m,noexec` for the runner's temp dirs), `--memory 512m`, `--cpus 1`, `--pids-limit 64`, `--cap-drop ALL`, `--security-opt no-new-privileges`, and an **internal network with no outbound access** (the API needs inbound only). With those in place, even a hypothetical escape from the Python subprocess cannot reach the internet. These flags are the supported hardening profile; deviations must be documented.

### 3.6 Logging and observability

- Log one line per request: request id, endpoint, `ok`, phases reached, source length, per-phase timings, status. **Never log the source text, generated Python, or program output** (rules.md §11; AGENTS.md §11).
- `X-Request-ID` header: accepted from the client if it matches `[A-Za-z0-9-]{8,64}`, else generated; echoed in the response.
- Runner failures that are *internal* (not user errors) are logged at `ERROR` with the request id.

### 3.7 Module layout

```
backend/
├── main.py               # CLI (I/O allowed)
├── api.py                # FastAPI app: routes, models, limiter, CORS, error handlers
├── nexora/
│   ├── pipeline.py       # compile_source(...)  (no I/O)
│   └── runner.py         # run_python(...), harness string
└── tests/
    ├── test_runner.py
    ├── test_api.py
    └── test_cli.py
```

`api.py` and `main.py` call `pipeline.compile_source` only; they contain no compiler logic.

## 4. Alternatives considered

1. **`exec()` in the server process** with a restricted `__builtins__`. Rejected: well-known to be escapable and cannot enforce time or memory.
2. **`RestrictedPython` / PyPy sandbox.** Extra dependencies and complexity; our structural whitelist plus a subprocess is simpler and stronger for such a tiny language.
3. **WebAssembly runtime (Pyodide) in the browser.** Attractive (no server execution), but ships a large runtime and bypasses the backend pipeline's runner story. Could be a future alternative target for the “Run” button.
4. **Docker container per run.** Strongest isolation, but 100s of ms of startup per run and Docker-in-Docker complexity. Container hardening of the whole API (§3.5) gives most of the benefit.
5. **WebSocket / server-sent streaming of output.** Nice for long programs, but adds protocol complexity; v1 returns output after the program ends (≤ 5 s).
6. **GraphQL.** Unnecessary for one main operation.
7. **Use `subprocess.run(timeout=…)` with `capture_output`.** Simpler, but a program that prints gigabytes would buffer them in memory before the timeout; the file-polling approach bounds it.

## 5. Drawbacks and risks

- Without OS-level limits on Windows, memory exhaustion is possible during local development; the risk is accepted for dev only and documented.
- Polling adds up to 20 ms of latency per run.
- An in-process rate limiter does not protect multi-worker deployments.
- `python -I -S` removes `site` features; if a future prelude needs the standard library, the harness must be revisited.
- Temp-directory creation per run costs a few ms; acceptable.

## 6. Impact on other components

- **RFC-0002:** `CompileResult` gains `cfg`, `optimization`, `python_line_map`, `timings_ms`.
- **RFC-0008:** the whitelist validator is a precondition of `run_python`.
- **Frontend (RFC-0010):** consumes `/compile`, `/examples`, `/language`; handles the error table above.
- **rules.md §11:** referenced as the security baseline; the Windows note must be mirrored there.

## 7. Test plan

**Runner**
- Normal program: stdout and `exit_code == 0`.
- Infinite loop (`during (yes) {}`) → `R5002` within `timeout + 0.5 s`; process is gone afterwards (no zombie).
- Print loop → `R5004`, stdout length ≤ cap.
- Division by zero → `R5001` with the right MiniLang line; deep recursion → `R5003`; global-before-init → `R5006` with the un-mangled name.
- Temp directory removed after success, failure, and kill.
- POSIX only (marked `skipif(windows)`): memory-hog program is stopped by `RLIMIT_AS` → `R5005`.
- The environment passed to the subprocess contains no secrets (assert on the dict).
- Validator rejects raw Python containing `import`; `run_python` is never given unvalidated code (pipeline test).

**API** (FastAPI `TestClient`)
- Valid program, invalid program (200 + `ok:false`), runtime error (200 + `ok:true` + `run.diagnostics`).
- `emit` subsetting returns `null` for omitted phases.
- 413, 422, 429 (+ `Retry-After`), 503, 500 shapes; no stack trace text in any body.
- CORS: allowed origin echoed, other origins not.
- `/language` content equals `tokens.KEYWORDS` and the error table.
- Log capture test: source text never appears in log output.

**CLI**
- Each `--emit` mode; exit codes `0/1/2/3`; stdout/stderr separation; stdin source via `-`.
