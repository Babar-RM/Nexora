# RFC-0008: Python Code Generation

- **Status:** Proposed
- **Author(s):** Nexora team
- **Created:** 2026-10-28
- **Depends on:** RFC-0001, RFC-0003, RFC-0004, RFC-0005, RFC-0007
- **Supersedes / Superseded by:** — / —

## 1. Summary

This RFC defines how an optimized, annotated MiniLang AST becomes Python 3.10+ source: the output layout, the mapping of every statement and expression, precedence-aware parenthesization (including Python's comparison-chaining trap), `int → float` widening, identifier renaming, the tiny runtime prelude, the **line map** used to translate runtime errors back to MiniLang lines, a whitelist validator for generated code, and the mapping from Python exceptions to Nexora runtime error codes.

## 2. Motivation

Generating *correct* Python is mostly about the places where Python and MiniLang differ quietly:

- Python's `a == b == c` is a **chained comparison**; MiniLang's is `(a == b) == c`.
- Python prints booleans as `True`/`False`; MiniLang prints `true`/`false`.
- Python has function scope, not block scope; MiniLang has block scope.
- MiniLang identifiers such as `class`, `def`, `print`, or `str` are legal but break or hijack Python.
- MiniLang requires explicit `int → float` widening to be preserved, e.g. so `show(p)` prints `2.0`.

This RFC pins those decisions down so the generator is testable and the output is deterministic and readable.

## 3. Detailed design

### 3.1 Interface

```python
@dataclass(frozen=True)
class GeneratedCode:
    code: str                       # Python source, ends with a single "\n"
    line_map: list[int]             # line_map[i] = MiniLang line for generated line i+1 (0 = prelude/header/blank)
    names: dict[str, str]           # renamed identifier -> original MiniLang name (empty if none renamed)

class PythonGenerator(NodeVisitor):
    target_name = "python"
    def generate(self, program: Program) -> GeneratedCode: ...
```

Satisfies the `CodeGenerator` protocol of RFC-0002 §3.8 (updated to return `GeneratedCode`). The generator imports only from `errors`, `ast_nodes`, `symbols`. It never reads TAC.

### 3.2 Output layout

```
<header comment>
<blank>
<prelude, only if the program contains a show statement>
<blank><blank>
<all task definitions, in source order, each followed by two blank lines>
<top-level statements, in source order>
```

1. **Header** (always, one line): `# Generated by Nexora (MiniLang -> Python). Do not edit.` — no timestamps or versions (determinism).
2. **Prelude** (only when needed):

```python
def __nx_show(value):
    if isinstance(value, bool):
        print("true" if value else "false")
    else:
        print(value)
```

`bool` is tested before anything else because `bool` is a subclass of `int`. Floats print through Python's `repr`-based `print`, which matches RFC-0001 §3.5 (`1.0`, `0.1`, `1e+16`).
3. **Tasks first.** MiniLang tasks are hoisted (callable before their declaration); Python `def`s are executed in order. Emitting all `def`s before top-level code makes every MiniLang call order valid in Python.
4. **Top-level statements** follow in source order. No `if __name__ == "__main__"` guard and no `main()` wrapper (keeps output flat and readable).
5. The file ends with exactly one `\n`. Indentation is 4 spaces. Line endings are `\n`.

### 3.3 Statement mapping

| MiniLang | Python |
|---|---|
| `make x = e;` / `x = e;` | `x = <e>` |
| widened `make`/assign/give/argument | `float(<e>)`, or the literal `2.0` when `<e>` is an `IntLiteral` that converts exactly (see 3.5) |
| `show(e);` | `__nx_show(<e>)` |
| `ask x: string;` | `x = input()` |
| `ask x: int;` | `x = int(input())` |
| `ask x: float;` | `x = float(input())` |
| `when (c) A` | `if <c>:` + suite |
| `when … otherwise B` | `else:` + suite |
| `otherwise when` (else branch is a `WhenStmt`) | `elif <c>:` (flattened into one chain) |
| `during (c) A` | `while <c>:` + suite |
| `give e;` / `give;` | `return <e>` / `return` |
| `stop;` | `break` |
| `skip;` | `continue` |
| expression statement `f(x);` | `f(x)` |
| `task f(a: int, b: float): int {…}` | `def f(a, b):` + suite (no annotations in output) |
| nested `Block` | its statements are emitted inline at the same indentation (Python has no block scope; RFC-0001 no-shadowing makes this safe) |

**Suites.** A suite with no emitted statements is rendered as `pass` (an empty `if`/`while`/`def` body). A `Block` that flattens to nothing inside a suite that has other statements contributes nothing.

**Give in a void task falls off the end.** Nothing is emitted for the implicit return.

### 3.4 Expressions and parenthesization

The generator uses an explicit precedence table for **Python**, and parenthesizes a child only when needed.

| Level | Python constructs | Notes |
|---|---|---|
| 1 | `or` (lowering of `either`) | |
| 2 | `and` (lowering of `both`) | |
| 3 | `not` | |
| 4 | `==  !=  <  <=  >  >=` | **all comparisons share this level** |
| 5 | `+  -` | |
| 6 | `*  /  %` | |
| 7 | unary `-` | |
| 8 | atoms: names, literals, calls, parenthesized | |

`needs_parens(child, parent, side)` is true when:

1. `level(child) < level(parent)`; or
2. `level(child) == level(parent)` and the child is on the **right** of a left-associative binary operator (e.g. `a - (b - c)`, `a / (b * c)`); or
3. **Comparison chaining rule:** parent and child are both level 4 (comparison/equality), on either side. MiniLang's `a == b == c` and `a < b == c < d` therefore become `(a == b) == c` and `(a < b) == (c < d)`. This preserves MiniLang's meaning and avoids Python's chaining.
4. A unary operator whose operand is itself unary: `-(-x)` is emitted with parentheses for readability (`not not x` is emitted as `not (not x)` for the same reason).
5. A call's arguments are emitted without extra parentheses.

Operator spellings: `both` maps to `and`, `either` maps to `or`, `not` maps to `not`, `==`, `!=`, `<`, `<=`, `>`, `>=`, `+`, `-`, `*`, `/`, `%` map to themselves. MiniLang `/` is Python `/` (true division) and `%` is Python `%` (floor modulo) — exactly the semantics fixed in RFC-0001 §3.6.

**Literals**

| Literal | Emission |
|---|---|
| int | `str(n)`; negative values (from folding) are emitted as `-5`, treated as level 7 (unary) for parenthesization |
| float | `repr(x)` (always contains `.`, `e`, or is `inf`/`nan`, which the optimizer never creates) |
| string | `repr(s)` — Python picks quoting and escapes correctly, including newlines, quotes, and non-printable characters |
| bool (`yes` / `no`) | `True` / `False` |
| `empty` | `None` |

### 3.5 Widening (`int → float`)

Driven by the flags the semantic analyzer wrote (RFC-0005 §3.7): `needs_widening` on `MakeStmt`, `AssignStmt`, `GiveStmt`, and `arg_widenings[i]` on `CallExpr`.

- If the expression is an `IntLiteral`, emit the float literal `repr(float(n))` (e.g. `2.0`). If `float(n)` would overflow (`OverflowError` for enormous ints), fall back to `float(<n>)` so the runtime raises the same error the source program would.
- Otherwise emit `float(<expr>)`.
- Mixed arithmetic needs nothing: Python promotes `int` to `float` exactly as MiniLang specifies.

### 3.6 Name handling

MiniLang identifiers are ASCII `[A-Za-z_][A-Za-z0-9_]*`, so they are valid Python identifiers except where they collide with reserved or used names. Before emitting, the generator collects **every identifier in the program** (variables, parameters, tasks) and builds a rename map:

```
RESERVED = set(keyword.kwlist) | {
    "print", "str", "float", "int", "bool", "isinstance", "repr",   # used by output or prelude
}
```

- A name in `RESERVED` becomes `name_`.
- If `name_` already exists as an identifier in the program (or was already assigned), append another `_` until unique. The result is deterministic (names are processed in sorted order).
- `__nx_`-prefixed names cannot occur in user programs (E3015), so `__nx_show` never collides.
- `GeneratedCode.names` maps renamed → original, used by the runner to translate error messages (`'class_'` → `'class'`).

Example: `make print = 1; make print_ = 2; show(print + print_);` → `print_` and `print__`.

### 3.7 Line map

The generator emits through a single helper `emit(text, source_line)` which appends the Python line and its MiniLang origin.

- Header, prelude, and blank separator lines map to `0`.
- A statement line maps to its node's `line` (folded or rewritten nodes keep their original position, RFC-0007 §3.2).
- `elif`/`else` lines map to the `WhenStmt`/`Block` that introduced them (`else` uses the `else` branch's block line; `elif` uses the nested `WhenStmt` line).
- A multi-line construct (e.g. `def`) maps its header line to the declaration line.

`len(line_map) == code.count("\n")` always holds (asserted).

### 3.8 Runtime error mapping

The runner (RFC-0009) obtains the exception type name and the *generated* line number from the subprocess, then:

| Python exception | Code | Message |
|---|---|---|
| `ZeroDivisionError` | `R5001` | `division or modulo by zero` |
| `RecursionError` | `R5003` | `maximum recursion depth exceeded` |
| `NameError` | `R5006` | `variable 'g' was used before it was initialized` (name un-mangled via `names`) |
| `OverflowError`, `MemoryError`, anything else | `R5005` | `the program failed while running: <short text>` |
| (runner) timeout / output cap | `R5002` / `R5004` | set by the runner, not by exceptions |

The MiniLang `line` comes from `line_map[python_line - 1]`; `0` means “unknown” and the diagnostic is reported without a position. Users never see Python tracebacks.

**Known limitation (R5006).** A task may read a global declared before it textually (RFC-0001 §3.4 rule 7), but a *call* to that task can occur before the global's `make` has executed:

```
show(f());          // runs before 'g' exists
make g = 1;
task f(): int { give g; }
```

Semantic analysis accepts this (it is a flow-sensitive property), and Python raises `NameError` at run time. v1 reports it precisely as `R5006` with the hint “move the call below the declaration of 'g'”. A static check (an `E3017` that follows the call graph) is a candidate for a later RFC.

### 3.9 Generated-code whitelist validator

Before the pipeline hands code to the runner, `validate_generated_python(code)` parses it with `ast.parse` and rejects (raising `InternalCompilerError`) any node outside this whitelist:

```
Module, FunctionDef, arguments, arg, Return, Assign, Expr, If, While, Pass, Break, Continue,
Call, Name, Constant, BinOp, UnaryOp, BoolOp, Compare, IfExp (prelude only),
Load, Store, Add, Sub, Mult, Div, Mod, USub, Not, And, Or, Eq, NotEq, Lt, LtE, Gt, GtE
```

Additionally: no `Attribute`, `Import`, `ImportFrom`, `Global`, `Nonlocal`, `Lambda`, `Try`, `With`, `Subscript`, `Starred`, `Await`, or comprehension nodes; every `Call` target is a `Name`; and every called `Name` that is not a user function is one of `{__nx_show, print, isinstance, float}` (prelude and widening). This makes it **structurally impossible** for any MiniLang program to generate code that imports modules, touches files, or reaches the network, a key defense-in-depth layer for RFC-0009.

### 3.10 Full example

MiniLang (`examples/factorial.mini`, the program from RFC-0001 §3.8; line numbers matter for the line map):

```
 1  // Compute and print factorials
 2  task factorial(n: int): int {
 3      when (n <= 1) {
 4          give 1;
 5      }
 6      give n * factorial(n - 1);
 7  }
 8
 9  make i = 1;
10  during (i <= 5) {
11      show(factorial(i));
12      i = i + 1;
13  }
14
15  make message = "done";
16  show(message + "!");
17  show(7 / 2);        // 3.5
18  show(7 % 2 == 1);   // true
```

Generated Python with optimization on (constant expressions folded):

```python
 1  # Generated by Nexora (MiniLang -> Python). Do not edit.
 2
 3  def __nx_show(value):
 4      if isinstance(value, bool):
 5          print("true" if value else "false")
 6      else:
 7          print(value)
 8
 9
10  def factorial(n):
11      if n <= 1:
12          return 1
13      return n * factorial(n - 1)
14
15
16  i = 1
17  while i <= 5:
18      __nx_show(factorial(i))
19      i = i + 1
20  message = "done"
21  __nx_show(message + "!")
22  __nx_show(3.5)
23  __nx_show(True)
```

`line_map`:

```
[0,0,0,0,0,0,0,0,0, 2,3,4,6, 0,0, 9,10,11,12, 15,16,17,18]
```

(23 entries, one per generated line.) Output when run: `1`, `2`, `6`, `24`, `120`, `done!`, `3.5`, `true`.

**Chaining trap example**

```
show(a == b == c);        // MiniLang: (a == b) == c, all bool
```
→ `__nx_show((a == b) == c)`

### 3.11 Determinism and readability rules

1. Same program and options → byte-identical output (no set/dict-order leakage; sort where order is not semantic).
2. No unnecessary parentheses beyond §3.4; no unnecessary blank lines beyond §3.2.
3. User variable and task names are preserved unless renamed per §3.6.
4. No comments inside the generated body in v1 (keeps the line map simple).

## 4. Alternatives considered

1. **Generate Python from TAC.** Rejected (RFC-0002 §3.3): requires structure recovery; output would be unreadable.
2. **Python's `ast` module + `ast.unparse`.** Works, but `ast.unparse` gives no line map control and hides the precedence decisions this RFC wants to specify and test. May be revisited as an implementation detail.
3. **Always parenthesize every sub-expression.** Safe but ugly output; rejected for readability.
4. **Print booleans with Python's native `True`/`False`.** Rejected: diverges from RFC-0001 and from future targets.
5. **Wrap top-level code in `def main():`.** Rejected: changes global/local semantics and clutters the output.
6. **Emit type annotations in Python (`def f(a: int) -> int:`).** Possible and harmless, but adds noise and no runtime value; reconsider if users ask for it.
7. **Renaming with a prefix (`nx_class`).** `name_` is closer to PEP 8 convention for keyword collisions and reads better.

## 5. Drawbacks and risks

- The comparison-chaining rule produces parentheses some users find noisy; correctness wins.
- R5006 is a runtime-only detection of a flow-sensitive error until a static check exists.
- The prelude adds seven lines to every output that uses `show`; acceptable and explicit.
- Python's `float(<huge int>)` and `int / int` overflow raise `OverflowError` where MiniLang semantics (RFC-0001 §3.6) leave floats “as Python does”; this is documented via R5005.

## 6. Impact on other components

- **RFC-0002:** `Phase 6` output becomes `GeneratedCode`; `CompileResult` gains `python_line_map`.
- **RFC-0004:** adds `R5006`.
- **RFC-0005 / RFC-0003:** `CallExpr.arg_widenings: list[bool]` replaces the ambiguous per-argument wording.
- **Runner (RFC-0009):** consumes `line_map` and `names`.
- **Frontend (RFC-0010):** Python panel highlights the originating MiniLang line using `line_map`.

## 7. Test plan

- **Per-construct unit tests:** each row of §3.3 and §3.4 (precedence matrix, right-associativity cases `a - (b - c)`, unary nesting, comparison chaining).
- **Golden files:** `tests/golden/*.mini` + `.py.expected` for every example, with optimization on and off.
- **Compile check:** `ast.parse(code)` succeeds for every valid fixture; `validate_generated_python` accepts all and rejects hand-crafted bad snippets (`import os`, attribute access, `exec(...)`).
- **Behaviour tests:** run generated code through the runner; stdout must equal the expected output declared in the fixture.
- **Name handling:** every keyword and builtin in `RESERVED`; collision chains (`print`, `print_`, `print__`); un-mangling in R5006/R5005 messages.
- **Line map:** length equals line count; spot checks for `def`, `elif`, `else`, folded expressions, and a runtime error (`show(1/z)` with `z = 0`) mapping to the right MiniLang line.
- **Widening:** literals (`make p: float = 2;` → `p = 2.0`), expressions (`float(a + b)`), arguments, returns, and the overflow fallback.
- **Determinism:** two generations are byte-identical.
- **R5006:** the known-limitation program reports R5006 with the original (un-mangled) name.

## 8. Open questions

1. Emit Python type annotations? (Proposed: no in v1.)

3. Should the prelude be inlined only when `show` is used, or always? (Proposed: only when used.)
