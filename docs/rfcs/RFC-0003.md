# RFC-0003: AST Design

- **Status:** Proposed
- **Author(s):** Nexora team
- **Created:** 2026-10-21
- **Depends on:** RFC-0001, RFC-0002
- **Supersedes / Superseded by:** — / —

## 1. Summary

This RFC defines the Abstract Syntax Tree: the complete catalogue of node classes, their fields, how positions are tracked, how semantic annotations are attached, how trees are traversed (visitor), how they are serialized to JSON, and how they are printed for debugging. The AST is the **shared contract** between the parser (producer) and the semantic analyzer, IR generator, optimizer, and code generator (consumers).

## 2. Motivation

All four team members touch the AST. If its shape is vague, the parser author and the semantic/codegen author will build incompatible assumptions. Fixing the node catalogue early lets the parser and the later phases be developed in parallel.

Design goals:

1. **Faithful to the grammar** (RFC-0001 §3.2): one node class per construct.
2. **Position-carrying:** every node knows its `line` and `column` for error messages.
3. **Plain data:** dataclasses, easy to construct in tests, easy to serialize.
4. **Annotatable:** semantic analysis attaches types and symbols without building a second tree.
5. **Traversable:** a visitor base class avoids giant `isinstance` chains.

## 3. Detailed design

### 3.1 Base classes

```python
from __future__ import annotations
from dataclasses import dataclass, field

@dataclass(kw_only=True)
class Node:
    """Base class for all AST nodes. line/column are 1-based, of the node's first token."""
    line: int
    column: int

@dataclass
class Expr(Node):
    """Base class for expressions. `type` is filled in by semantic analysis."""
    # Declared on each concrete class (see 3.4) to keep dataclass field ordering valid.

@dataclass
class Stmt(Node):
    """Base class for statements."""
```

Notes:
- `kw_only=True` on `Node` makes `line`/`column` keyword-only so subclasses can declare positional fields freely. Construct nodes as `BinaryExpr("+", left, right, line=3, column=9)`.
- Python 3.10+ is required for `kw_only`.

### 3.2 Node catalogue

**Program and declarations**

| Node | Fields | Grammar rule |
|---|---|---|
| `Program` | `body: list[Stmt | FunctionDecl]` | `program` |
| `FunctionDecl` | `name: str`, `params: list[Param]`, `return_type: TypeRef | None`, `body: Block` | `functionDecl` |
| `Param` | `name: str`, `type_ref: TypeRef` | `param` |
| `TypeRef` | `name: str` | `typeName` |

**Statements**

| Node | Fields | Grammar rule |
|---|---|---|
| `Block` | `statements: list[Stmt]` | `block` |
| `LetStmt` | `name: str`, `declared_type: TypeRef | None`, `initializer: Expr` | `letStmt` |
| `AssignStmt` | `name: str`, `value: Expr` | `assignStmt` |
| `IfStmt` | `condition: Expr`, `then_block: Block`, `else_branch: Block | IfStmt | None` | `ifStmt` |
| `WhileStmt` | `condition: Expr`, `body: Block` | `whileStmt` |
| `ReturnStmt` | `value: Expr | None` | `returnStmt` |
| `ShowStmt` | `value: Expr` | `showStmt` |
| `ExprStmt` | `expression: Expr` | `exprStmt` |

`FunctionDecl` appears only in `Program.body` (never in a `Block`). `Block` may also appear as a statement (a nested bare block).

**Expressions**

| Node | Fields | Grammar rule |
|---|---|---|
| `IntLiteral` | `value: int` | `INT` |
| `FloatLiteral` | `value: float` | `FLOAT` |
| `StringLiteral` | `value: str` | `STRING` |
| `BoolLiteral` | `value: bool` | `true` / `false` |
| `Identifier` | `name: str` | `IDENT` |
| `UnaryExpr` | `op: str` (`"-"`, `"not"`), `operand: Expr` | `unary`, `notExpr` |
| `BinaryExpr` | `op: str`, `left: Expr`, `right: Expr` | `orExpr` … `factor` |
| `CallExpr` | `callee: str`, `args: list[Expr]` | `call` |

Operator strings are exactly: `or and == != < <= > >= + - * / %` (binary) and `- not` (unary). Parenthesised expressions produce **no node**; grouping is encoded by tree shape.

Why `callee: str` and not an `Identifier` node: RFC-0001 allows calls only on names, and a function name is not a value expression.

### 3.3 Position rules

| Node | `line`/`column` taken from |
|---|---|
| `LetStmt`, `IfStmt`, `WhileStmt`, `ReturnStmt`, `ShowStmt`, `FunctionDecl` | the keyword token |
| `AssignStmt` | the identifier token |
| `ExprStmt` | the first token of the expression |
| `Block` | the `{` token |
| `Param` / `TypeRef` | the first token of that part |
| literals, `Identifier` | the literal/identifier token |
| `UnaryExpr` | the operator token |
| `BinaryExpr` | the **operator** token (so “cannot apply `+` to int and string” points at the `+`) |
| `CallExpr` | the callee identifier token |
| `Program` | line 1, column 1 |

End positions are not stored in v1. Diagnostics may compute an underline length from the name or lexeme.

### 3.4 Semantic annotations

Semantic analysis fills fields that the parser leaves as `None`. They are excluded from equality and `repr` so tests can compare parsed trees without annotations.

```python
@dataclass
class IntLiteral(Expr):
    value: int
    type: "Type | None" = field(default=None, compare=False, repr=False)

@dataclass
class Identifier(Expr):
    name: str
    type: "Type | None" = field(default=None, compare=False, repr=False)
    symbol: "Symbol | None" = field(default=None, compare=False, repr=False)

@dataclass
class CallExpr(Expr):
    callee: str
    args: list[Expr]
    type: "Type | None" = field(default=None, compare=False, repr=False)
    symbol: "Symbol | None" = field(default=None, compare=False, repr=False)
```

Every concrete `Expr` subclass has `type`. Only `Identifier`, `CallExpr`, `LetStmt`, `AssignStmt`, `FunctionDecl`, and `Param` have a `symbol`. `Type` and `Symbol` are defined in `symbols.py` (RFC-0005); `ast_nodes.py` uses forward references only (`from __future__ import annotations` plus `TYPE_CHECKING` imports) so the import direction stays one-way.

After a successful semantic phase, **no `Expr.type` is `None`** (invariant checked in tests).

### 3.5 Traversal: visitor

```python
class NodeVisitor:
    """Dispatches to visit_<ClassName>; falls back to generic_visit."""

    def visit(self, node: Node):
        method = getattr(self, f"visit_{type(node).__name__}", self.generic_visit)
        return method(node)

    def generic_visit(self, node: Node):
        for child in iter_children(node):
            self.visit(child)
```

`iter_children(node)` yields every child `Node` in source order (it knows each class's fields). Semantic analysis, IR generation, optimization, and code generation each subclass `NodeVisitor` (or `NodeTransformer`, which returns replacement nodes for optimizer rewrites).

### 3.6 Serialization

Every node implements `to_dict()` (via one shared function in `ast_nodes.py`) producing JSON-safe data:

```json
{
  "type": "BinaryExpr",
  "op": "+",
  "line": 1, "column": 15,
  "left":  { "type": "Identifier", "name": "a", "line": 1, "column": 13, "resolved_type": "int" },
  "right": { "type": "Identifier", "name": "b", "line": 1, "column": 17, "resolved_type": "int" }
}
```

Rules:
- `"type"` is always the node class name (the semantic type is exported as `"resolved_type"` to avoid the clash).
- Child nodes become nested objects; lists become arrays.
- Annotations appear only if set.

### 3.7 Pretty printer

`dump(node) -> str` returns an indented tree for the CLI and tests, e.g.

```
Program
  LetStmt result
    BinaryExpr +
      IntLiteral 2
      BinaryExpr *
        IntLiteral 3
        IntLiteral 4
  ShowStmt
    Identifier result
```

### 3.8 Worked example

Source: `let result = 2 + 3 * 4; show(result);`

```python
Program(body=[
  LetStmt(name="result", declared_type=None,
          initializer=BinaryExpr("+",
              IntLiteral(2, line=1, column=14),
              BinaryExpr("*", IntLiteral(3, line=1, column=18),
                              IntLiteral(4, line=1, column=22), line=1, column=20),
              line=1, column=16),
          line=1, column=1),
  ShowStmt(value=Identifier("result", line=1, column=31), line=1, column=26),
], line=1, column=1)
```

### 3.9 Invariants (tested)

1. Every node has positive `line` and `column`.
2. `FunctionDecl` occurs only directly in `Program.body`.
3. `IfStmt.else_branch` is `None`, a `Block`, or an `IfStmt`.
4. `UnaryExpr.op ∈ {"-", "not"}`; `BinaryExpr.op` ∈ the binary operator set.
5. No node is shared between two parents (the AST is a tree, not a DAG) — so optimizer rewrites cannot corrupt other branches.
6. After semantic analysis: every `Expr.type` is set; every `Identifier`/`CallExpr` has a `symbol`.

## 4. Alternatives considered

1. **Dicts / generic `Node(kind, children)`.** Rejected: no type checking, typo-prone field names, poor editor support.
2. **Separate “typed AST”.** Rejected: duplicates the whole tree; annotations on the same tree are simpler.
3. **Immutable (frozen) nodes with rebuilding.** Attractive, but semantic annotation and optimizer rewriting get more verbose. Mutable dataclasses plus the rule “only semantic annotation and `NodeTransformer` may mutate” is a pragmatic middle ground.
4. **Node for parentheses (`GroupExpr`).** Rejected: tree shape already encodes grouping; a node adds noise to every consumer.
5. **Operators as enums.** Considered; plain strings are simpler to print, serialize, and map to Python. Parser validates the set.
6. **`CallExpr.callee` as an `Expr`.** Rejected for v1 (no first-class functions); easy to widen later.

## 5. Drawbacks and risks

- Mutable annotations mean a tree must not be reused across two different semantic analyses; the pipeline always builds a fresh tree per compile.
- Strings for operators and type names defer some validation to the parser/semantic phase.
- Storing only start positions limits precise underlining; acceptable for v1.

## 6. Impact on other components

- **Parser:** constructs exactly these nodes with the position rules of §3.3.
- **Semantic analyzer:** fills `type`/`symbol` (RFC-0005).
- **IR / optimizer / codegen:** subclass `NodeVisitor`/`NodeTransformer`.
- **Frontend:** consumes the `to_dict()` shape of §3.6 for the AST viewer.
- Any change to this RFC needs approval from all phase owners (rules.md §4.6).

## 7. Test plan

- Construct each node class; check `to_dict()` and `dump()` output.
- `iter_children` returns children in source order for every node type.
- Visitor dispatch: specific method, fallback, and traversal order.
- Invariant checker function (`validate_ast(program)`) used by parser tests on every fixture.
- Position tests: for a fixed source, assert the `line`/`column` of each node per §3.3.
- Round-trip sanity: parse → `to_dict` → JSON → compare to a stored golden JSON for a sample program.

## 8. Open questions

1. Add `end_line`/`end_column` for precise error underlines? (Proposed: later, additive.)
2. Should `TypeRef` carry its own position for E3014 “unknown type name” errors? (Proposed: yes — it already does via `Node`.)
3. A `NodeTransformer` base for the optimizer: define in this RFC or RFC-0007? (Proposed: define in `ast_nodes.py` now, document in RFC-0007.)
