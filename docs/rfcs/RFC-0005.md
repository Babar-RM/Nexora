# RFC-0005: Semantic Analysis, Type System, and Symbol Table

- **Status:** Proposed
- **Author(s):** Nexora team
- **Created:** 2026-10-21
- **Depends on:** RFC-0001, RFC-0003, RFC-0004
- **Supersedes / Superseded by:** — / —

## 1. Summary

This RFC specifies the semantic analysis phase: the `Type` model, the typing rules for every operator and statement, scope and name-resolution rules, the `Symbol`, `Scope`, and `SymbolTable` classes, the two-pass algorithm, the missing-return analysis, what annotations are written onto the AST, and how errors are reported.

## 2. Motivation

The parser only knows that a program is *shaped* correctly. Semantic analysis decides whether it *means* something valid: names exist, types fit, calls match declarations, functions return. It is also the phase that makes later phases simple: after it succeeds, the IR generator and code generator can assume validity and never re-check.

## 3. Detailed design

### 3.1 Types

```python
from enum import Enum
from dataclasses import dataclass

class Type(Enum):
    INT = "int"
    FLOAT = "float"
    STRING = "string"
    BOOL = "bool"
    VOID = "void"
    ERROR = "error"      # poisoned type, used to suppress cascading errors

@dataclass(frozen=True)
class FunctionType:
    params: tuple[Type, ...]
    ret: Type            # Type.VOID for functions without a return type
```

Helpers (in `symbols.py`):

- `is_numeric(t)` → `t in (INT, FLOAT)`.
- `is_assignable(target, source)` → `True` if `source == target`, or `target == FLOAT and source == INT` (widening), or either is `ERROR`.
- `type_from_name(name)` → `Type` for `"int" | "float" | "string" | "bool"`, else `None` (→ E3014). `"void"` is rejected in user annotations in v1.

`ERROR` is compatible with everything and produces no further diagnostics.

### 3.2 Typing rules

Let `ε` denote an expression and `T(ε)` its type.

**Literals and names**

| Expression | Type |
|---|---|
| `IntLiteral` | `INT` |
| `FloatLiteral` | `FLOAT` |
| `StringLiteral` | `STRING` |
| `BoolLiteral` | `BOOL` |
| `Identifier x` | the declared type of `x` (E3001 if undeclared; E3007 if `x` is a function used as a value) |

**Unary**

| Op | Operand | Result | Else |
|---|---|---|---|
| `-` | `INT` / `FLOAT` | same | E3004 |
| `not` | `BOOL` | `BOOL` | E3004 |

**Binary**

| Op | Operand types | Result |
|---|---|---|
| `+` | `INT,INT` | `INT` |
| `+` | numeric mix with at least one `FLOAT` | `FLOAT` |
| `+` | `STRING,STRING` | `STRING` |
| `-` `*` | `INT,INT` | `INT` |
| `-` `*` | numeric mix with a `FLOAT` | `FLOAT` |
| `/` | any numeric pair | `FLOAT` |
| `%` | `INT,INT` | `INT` |
| `%` | numeric mix with a `FLOAT` | `FLOAT` |
| `<` `<=` `>` `>=` | both numeric, or both `STRING` | `BOOL` |
| `==` `!=` | both numeric, or both `STRING`, or both `BOOL` | `BOOL` |
| `and` `or` | `BOOL,BOOL` | `BOOL` |

Anything else is **E3004** `cannot apply '<op>' to <left> and <right>`. If either operand is `ERROR`, the result is `ERROR` and no diagnostic is added.

**Calls** `f(a1, …, an)`

1. `f` must resolve to a function symbol (E3001 if unknown, E3007 if it is a variable).
2. `n` must equal the parameter count (E3006).
3. Each `ai` must be assignable to the parameter type (E3008, 1-based argument index in the message).
4. `T(call)` is the function's return type (possibly `VOID`).

**`VOID` usage (E3013):** a `VOID` value may appear only as the entire expression of an `ExprStmt`. It may not be used as an operand, argument, initializer, assigned value, condition, returned value, or `show` argument.

### 3.3 Statement rules

| Statement | Rule | Error |
|---|---|---|
| `let x = e;` | `T(e)` not `VOID`; declare `x : T(e)` | E3013 |
| `let x: T = e;` | `T` known (E3014); `T(e)` assignable to `T`; declare `x : T` | E3014, E3003 |
| `x = e;` | `x` declared and a variable; `T(e)` assignable to `T(x)`; `x` not a global when inside a function | E3001, E3003, E3009 |
| `if (c)`, `while (c)` | `T(c) == BOOL` | E3005 |
| `return e;` | inside a function (E3010); non-void function: `T(e)` assignable to return type; void function: no value | E3010, E3011 |
| `return;` | inside a function; function must be void | E3010, E3011 |
| `show(e);` | `T(e)` not `VOID` | E3013 |
| `ExprStmt` | any, including `VOID` call | — |
| `function f(...)` | duplicate name (E3016); parameter types known (E3014); param names unique (E3016) and not reserved (E3015); body returns on every path if non-void (E3012) | see left |

Reserved-name check (E3015) applies to every declared name (variables, functions, parameters): the names `int float string bool void` and any identifier starting with `__nx_`.

### 3.4 Scopes and name resolution

```python
class ScopeKind(Enum):
    GLOBAL = "global"
    FUNCTION = "function"
    BLOCK = "block"

class SymbolKind(Enum):
    VARIABLE = "variable"
    PARAMETER = "parameter"
    FUNCTION = "function"

@dataclass
class Symbol:
    name: str
    kind: SymbolKind
    type: Type | FunctionType
    line: int
    column: int
    scope_kind: ScopeKind          # where it was declared
    order: int                     # declaration sequence number within the compilation
    used: bool = False             # for W4003

class Scope:
    def __init__(self, kind: ScopeKind, parent: "Scope | None"):
        self.kind = kind
        self.parent = parent
        self.symbols: dict[str, Symbol] = {}

class SymbolTable:
    def push(self, kind: ScopeKind) -> Scope: ...
    def pop(self) -> Scope: ...                 # pops and records the scope in history
    def declare(self, symbol: Symbol) -> bool: ...   # False if it conflicts
    def lookup(self, name: str) -> Symbol | None: ... # walks parent chain
    def lookup_current(self, name: str) -> Symbol | None: ...
    @property
    def in_function(self) -> bool: ...
    def snapshot(self) -> list[dict]: ...       # every symbol ever declared, for the UI
```

Rules:

1. **Resolution** walks from the innermost scope outward and returns the first match.
2. **No shadowing (E3002):** `declare` fails if `lookup(name)` finds *any* symbol visible from the current scope (variables, parameters, or functions in any enclosing scope, including global). Sibling scopes are unaffected because popped scopes are not visible.
3. **Functions are hoisted:** pass 1 declares all top-level functions in the global scope before any body is analyzed.
4. **Globals in functions (read):** a global *variable* is visible inside a function body only if it is declared textually before the function. Because pass 2 walks top-level items in order and declares globals as it meets them, a not-yet-declared global is simply unresolved (E3001). Add the hint: `global variables must be declared before the function that uses them`.
5. **Globals in functions (write):** assignment to a symbol whose `scope_kind` is `GLOBAL` and `kind` is `VARIABLE`, while `in_function`, is E3009.
6. **Symbol history:** `pop` appends the scope's symbols to a history list, so `snapshot()` can report symbols of closed scopes (the UI shows every symbol with its scope and type).

### 3.5 Algorithm

```
analyze(program):
    table = SymbolTable(); push(GLOBAL)

    # Pass 1 — hoist functions
    for each FunctionDecl f in program.body:
        resolve param types (E3014), check reserved names (E3015)
        build FunctionType(params, ret)
        declare Symbol(f.name, FUNCTION, ...)   -> E3016 on duplicate
        f.symbol = symbol

    # Pass 2 — walk in order
    for item in program.body:
        if FunctionDecl:  analyze_function(item)
        else:             analyze_statement(item)

    # Post
    emit W4003 for unused variables (not parameters, not functions)
    return SemanticResult(program, table.snapshot(), diagnostics)

analyze_function(f):
    push(FUNCTION); declare each Param as PARAMETER (E3002/E3016 on clash)
    analyze_block_body(f.body)        # body's own block does NOT push a second scope
    if f.return_type != void and not always_returns(f.body):  E3012 at f's position
    pop()

analyze_statement / analyze_expression:
    visitor methods per node type (NodeVisitor), each returning the expression's Type
    and storing it in node.type
```

Notes:

- A function's parameters and its body's top-level declarations share one scope (so `function f(x: int) { let x = 1; }` is E3002).
- Each nested `{ }` (including `if`/`while` bodies) pushes a `BLOCK` scope.
- The initializer of `let x = e;` is analyzed **before** `x` is declared, so `let x = x + 1;` reports E3001 for the right-hand `x`.
- Recursive calls work because the function's symbol exists from pass 1.

### 3.6 Missing-return analysis

`always_returns(stmt)` is a conservative structural check:

| Statement | Returns on all paths if… |
|---|---|
| `ReturnStmt` | always |
| `Block` | any statement in it always returns (statements after it are unreachable → W4001) |
| `IfStmt` | it has an `else` branch **and** both `then` and `else` always return |
| `WhileStmt` | never (conservative, even for `while (true)`) |
| everything else | never |

A non-void function for which `always_returns(body)` is false gets E3012 (reported at the function's name position). Void functions are exempt.

Unreachable code (W4001): the first statement after an always-returning statement in the same block.

### 3.7 Annotations written onto the AST

Per RFC-0003 §3.4:

- `expr.type` — the `Type` of every expression (`FunctionType` is never an expression type).
- `Identifier.symbol`, `CallExpr.symbol` — the resolved `Symbol`.
- `LetStmt.symbol`, `Param.symbol`, `FunctionDecl.symbol` — the declared symbol.
- For widening (`int → float`) the analyzer does **not** insert conversion nodes; the code generator uses `type` information (target type `FLOAT`, source `INT`) to emit explicit `float(...)` where needed (RFC-0008). To make that decidable, `LetStmt`, `AssignStmt`, `CallExpr` arguments, and `ReturnStmt` record `needs_widening: bool` (set by the analyzer).

### 3.8 Output

```python
@dataclass
class SemanticResult:
    program: Program                  # annotated in place
    symbols: list[dict]               # SymbolTable.snapshot()
    diagnostics: list[Diagnostic]
    @property
    def ok(self) -> bool: ...
```

Symbol export shape (for the UI):

```json
{ "name": "total", "kind": "variable", "type": "int", "scope": "global", "line": 3, "column": 5 }
```

Function types render as `(int, int) -> int`.

### 3.9 Worked example

```
let a = 10;
let b = "x";
let c = a + b;          // E3004 cannot apply '+' to int and string (at the '+')
if (a) { show(c); }     // E3005 condition must be bool, found int ; no error for 'c' (type ERROR)
function f(n: int): int { show(n); }   // E3012 does not return on every path
show(f(1, 2));          // E3006 function 'f' expects 1 argument, got 2
```

Diagnostics are emitted in source order with no cascades from `c`.

## 4. Alternatives considered

1. **Single pass (no hoisting).** Simpler but forbids mutual recursion and calling a function above its declaration; hoisting is cheap.
2. **Full Hindley–Milner inference.** Overkill: MiniLang has no generics or first-class functions. Local inference for `let` is enough; parameter annotations are mandatory.
3. **Allow shadowing, mangle names in codegen.** Possible later; v1 prefers the stricter rule for clearer Python output.
4. **Insert explicit cast nodes for widening.** Cleaner for later phases but changes the AST shape; the `needs_widening` flag is a lighter alternative. Revisit if more conversions are added.
5. **Treat `while (true)` as always-returning via constant analysis.** Rejected for v1; conservative rule is simple and safe.

## 5. Drawbacks and risks

- The no-shadowing rule may surprise users; messages and hints must explain it.
- “Globals must be declared before the function” is an unusual rule; it exists to keep Python semantics identical and to avoid dependence on execution order. Hints mitigate confusion.
- Conservative return analysis may reject programs that are fine in practice (e.g. `while (true) { return 1; }`). Users can restructure; the error is explicit.

## 6. Impact on other components

- **AST (RFC-0003):** adds `symbol` fields and `needs_widening` flags; the parser leaves them default.
- **Diagnostics (RFC-0004):** uses E3001–E3016, W4001–W4003 and the `ERROR`-type suppression.
- **IR generator:** may assume names resolve and types match; reads `type`/`symbol`.
- **Code generator:** reads `needs_widening` and symbol names (for keyword-collision renaming).
- **Frontend:** displays `symbols` as a table.

## 7. Test plan

- **Per rule:** one valid and one invalid program for every row of §3.2 and §3.3.
- **Per code:** E3001–E3016 and W4001–W4003 each have a test asserting code, line, and column.
- **Scoping:** sibling blocks may redeclare; shadowing is rejected in nested blocks, parameters, and against globals and functions; use of a variable after its block ends is E3001.
- **Hoisting:** calling a function before its declaration works; mutual recursion works; global declared after a function and used inside it is E3001.
- **Globals:** read inside a function OK; assignment inside a function is E3009.
- **Return analysis:** if/else both return OK; if without else is E3012; while is E3012; W4001 for code after `return`.
- **Cascade suppression:** `let a = b + c;` yields exactly two E3001; `ERROR` flows through operators silently.
- **Invariant test:** after a successful analysis of every valid fixture, every `Expr.type` is non-`None` and never `ERROR`, and every `Identifier`/`CallExpr` has a `symbol`.
- **Symbol snapshot:** includes symbols from closed scopes with correct scope names.
- **Widening:** `let p: float = 1;`, `float` parameter with an `int` argument, and return widening set `needs_widening`.

## 8. Open questions

1. Should unused-variable warnings (W4003) include function parameters? (Proposed: no.)
2. Should `let` without annotation be allowed to infer `FLOAT` from an int literal with a decimal-looking name (e.g. `let x = 1.0`)? (Already `FLOAT` by literal type; no change.)
3. Should shadowing of a *global function* by a local variable be allowed? (Proposed: no — consistent with the no-shadowing rule.)
4. Explicit conversion functions (`float(x)`, `int(x)`, `string(x)`) in a later RFC? (Proposed: yes, as built-ins, after the core pipeline is complete.)
